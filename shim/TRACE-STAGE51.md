# Stage 51: Cactus visible native-XNU framebuffer console (XNU rebuilt)

**Status (2026-10-24):** Stage51 kernel, payload and **boot image BUILT**.
The new Stage51-specific relocated Mach-O/ADT static checker passed,
along with 40 Ubuntu shim tests and Android boot-header validation.
Stage51 has NOT been flashed or hardware-tested; native XNU framebuffer
text and full OS startup remain unproven. Stage49 green/magenta scanout
was previously confirmed by the device owner.

## Why Stage50 alone was insufficient

Stage50 changed XNU's `boot_args.Video.v_baseAddr` to the physical
LK OVL0 layer1 buffer (`0x7f4db000`) only after Stage49's guards.
The earlier XNU kernel still had the invisible `0x5e605000` value
embedded in its Cactus early-console page tables, and its Apple ADT
`sweet-fbcon` property was likewise stale. Kernel print routines
cannot become visible through a boot_args-only fix.

## Implemented in Stage51 source

- `xnu/patches/0088-cactus-live-lk-layer1-console.patch` is an
  ordered patch after 0087. It retargets the Cactus early framebuffer
  constants, assembly Stage0 pixel marker, bootstrap KVA map, and
  post-MMU `sweet_early_map_final` tables. Shared SWEET behavior
  remains unchanged.
- LK layer1 base `0x7f4db000`, pitch `2880`, dimensions `720x1440`;
  length `0x3f4800`. Three aligned 2MiB blocks map
  `0x7f400000..0x7fa00000`; the PA offset `0xdb000` plus the
  framebuffer length is `0x4cf800`, exceeding two blocks.
- `tools/mkadt.py` generates Cactus's `sweet-fbcon` node at the
  actual LK layer1 physical address. The stage-specific option of
  `tools/stage27_pack_kernel.py` also replaces the old baseline
  payload's ADT console property without changing the rest of its ADT.
- `shim/build_trace_probe.sh 51` requires
  `shim/out/cactus/payload-stage51.bin`, preserving the known-good
  Stage28 and Stage50 payloads and images. It retains the Stage49
  physical display guards, the Stage50 boot_args redirection and
  unbounded native XNU handoff, and emits `0x5100` before handoff.
  The decoder's `--require-stage51` checks the new marker;
  **0x5100 does not prove native kernel output**.
- Patch 0088 labels early native XNU text `CACTUS-XNU-STAGE51`,
  clamps the stage bars to 720 display pixels, and places a memory
  barrier after each early text line. Clang optimizes the short string
  out of the linked Mach-O (the old SWEET label was also absent).
  The packer therefore accepts either that string or the exact SHA256
  of the successfully compiled and audited Stage51 kernel; it still
  rejects an unrecognized/Stage28 Mach-O.
- `shim/run-stage49.ps1 -Stage 51` checks the exact image hash
  generated by the Stage51 build, verifies fastboot product `cactus`,
  and starts an independent USB watcher before the flash.

The existing `sweet-fbcon` character transmit and XNU `sweet_early`
mark/panic routines are inherited from the XNU patch series.
Their output is a hypothesis until native code reaches them on hardware.
The console and COM25 recorder are separate paths: XNU does not yet
invoke a returnable EL1-to-EL2 USB logging hook for every print.
